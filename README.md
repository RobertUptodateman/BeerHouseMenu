# BeerHouseMenu

Технический каркас статичного меню бара: одностраничный сайт на GitHub Pages и веб-админка Decap CMS для правки данных.

## Цель

Меню бара для телевизора над стойкой с оперативной правкой через веб-админку.

- **Этап 1 (готов):** каркас на одной карточке пива. Работает цепочка «вход в админку → изменение данных → коммит в репозиторий → обновление на сайте».
- **Этап 2 (текущий):** дизайн меню и список позиций (от 24 и больше) на одном экране.

Репозиторий: [RobertUptodateman/BeerHouseMenu](https://github.com/RobertUptodateman/BeerHouseMenu.git).

## Технические требования

### Публичная часть

- Один HTML-файл: `index.html`.
- Данные из `data/menu.json`.
- При загрузке и далее каждые 30–60 секунд — `fetch` JSON.
- После смены JSON меню обновляется без ручной перезагрузки страницы.
- Если JSON временно недоступен, страница не ломается: остаются последние успешные данные и короткое сообщение об ошибке.

### Дизайн

- Выглядит как меню: строка «номер крана, цветной маркер, пивоварня, название сорта, стиль — ABV, IBU, цена».
- Иерархия текста: «Пивоварня / Сорт». Сорт самый крупный, жирный и тёмный; пивоварня тоже жирная, но чуть мельче и светлее; стиль строкой ниже, того же размера, что пивоварня, но обычным начертанием и серым.
- Метки сорта (выбираются в админке): NEW и LAST KEG — цветная плашка после названия.
- Номер крана тем же шрифтом и размером, что ABV.
- ABV, IBU, объём и цена одного размера; у цены сумма жирная и тёмно-зелёная, знак ₾ обычным начертанием.
- Без названия бара вверху. Светлый фон, палитра по логотипу (`small_logo.jpg`): зелёный хмеля `#18634A` для заголовков колонок, более тёмный `#0B4F3A` для цен, неоново-жёлтый `#E8EC94` для плашек Core beer / Guest beer. Цвета — переменные в начале `<style>` в `index.html`.
- Экономия места: без карточек, рамок и лишних отступов; позиции разделены тонкой неакцентной чертой.
- Всегда две колонки: слева базовые краны (Core), справа гостевые (Guest).
- Номер крана считается по порядку: сверху вниз по базовым, затем продолжается в гостевых.
- Номер крана, ABV и IBU — крупным шрифтом, но меньше названия. Стили пишутся по-английски, по-русски — только некоторые названия.
- Цена в лари (₾). Рядом с ценой указан объём бокала: 0,33 или стандартный 0,45.
- Заголовки колонок: «Core beer» и «Guest beer».
- Номер крана и маркер стоят по центру строки по высоте; шильдик FRUIT/VEG занимает всю высоту строки.
- Маркер цвета пива: для светлого, янтарного/красного и тёмного — контрастный кружок; для фруктового и овощного — вертикальный шильдик с надписью `FRUIT` или `VEG`.
- Телевизор в альбомной ориентации: всё меню всегда на одном экране, без прокрутки и перелистывания.
- Размер шрифта подбирается автоматически под экран и число позиций. Скрипт пробует два варианта строки (стиль рядом с названием или под ним) и выбирает самый крупный шрифт, при котором всё помещается. Оставшаяся высота делится между строками.
- Позиции с `available: false` остаются в списке приглушёнными, цена зачёркнута.
- Шрифты из Google Fonts: Roboto Condensed и знак ₾ из Noto Sans Georgian (в шрифтах телевизоров его может не быть).

### Админ-часть

- Путь: `/admin/`.
- Decap CMS.
- Редактирование одного JSON-файла: общий список кранов с жёлтым разделителем «Гостевые краны». Позиции добавляются, удаляются и переставляются перетаскиванием; перетаскивание через разделитель переносит позицию в другую колонку. Сам разделитель тоже можно перетаскивать.
- У каждой позиции в списке виден номер крана («Кран 1» … «Кран N»); после перетаскивания номера обновляются сразу. Номера ставит скрипт в `admin/index.html`: он опирается на метки в классах Decap (`SortableListItem`, `TopBar`) и на текст «ГОСТЕВЫЕ КРАНЫ» в summary разделителя; при смене версии Decap или этого текста их стоит проверить.
- Цвет пива и бокал выбираются из списков.
- Сохранение создаёт коммит в репозиторий.

### Инфраструктура

- Хостинг: GitHub Pages (полностью статический сайт).
- Вход в админку: GitHub OAuth.
- OAuth-прокси: Cloudflare Worker.
- Один общий GitHub-аккаунт для доступа в админку.
- Worker также отдаёт меню по адресу `/menu`: читает `data/menu.json` из репозитория через GitHub API, не дожидаясь сборки Pages.
- Секреты (`Client ID`, `Client Secret`, `MENU_TOKEN`) хранятся только в Worker.

## Поток данных

1. Пользователь открывает `/admin/`.
2. Decap CMS инициирует вход через Cloudflare Worker.
3. Worker проводит OAuth с GitHub и возвращает `access_token`.
4. Токен сохраняется в `localStorage` браузера.
5. Пользователь правит список позиций в Decap CMS.
6. При сохранении Decap CMS коммитит обновлённый JSON в репозиторий.
7. Публичная страница раз в 15 с запрашивает Worker `/menu`, который сразу видит новый коммит (кэш Worker — 5 с). Меню обновляется примерно через 5–20 с после сохранения.
8. Если Worker недоступен, страница берёт `data/menu.json` с Pages. Там новые данные появляются только после сборки Pages и истечения кэша CDN (от ~1 до нескольких минут).

```
Браузер /admin/
  → Decap → Worker /auth
  → GitHub OAuth
  → Worker /callback → access_token → localStorage
  → Save → GitHub Contents API (commit JSON)
  → index.html каждые 15 с → Worker /menu → GitHub API → меню
                  (запасной путь: data/menu.json с Pages)
```

## Структура данных

`data/menu.json` — один общий список `taps`. В нём два типа элементов: `beer` (позиция) и `divider` (разделитель). Всё выше разделителя — базовые краны (левая колонка), ниже — гостевые (правая). Номер крана не хранится, а считается по порядку позиций, разделитель не считается. Если разделителя нет, все позиции идут в левую колонку.

```json
{
  "taps": [
    {
      "type": "beer",
      "brewery": "Big Village",
      "name": "Hazy IPA",
      "style": "New England IPA",
      "abv": 6,
      "ibu": 40,
      "color": "light",
      "glass": "0.45",
      "price": 12,
      "available": true
    },
    { "type": "divider", "column": "guest" }
  ]
}
```

Поля позиции:

| Поле | Смысл |
|---|---|
| `brewery` | пивоварня (необязательно) |
| `name` | название сорта |
| `style` | стиль (на английском) |
| `abv` | крепость, % |
| `ibu` | горечь (IBU), `0` показывается как «—» |
| `color` | маркер: `light`, `amber`, `dark`, `fruit` (шильдик FRUIT), `veg` (шильдик VEG) |
| `glass` | бокал: `0.45` (стандарт) или `0.33` |
| `badge` | метка рядом с названием (необязательно): `new` — NEW, `last` — LAST KEG |
| `price` | цена в лари |
| `available` | наличие (`true` / `false`) |

## Структура репозитория

Минимум файлов, без сборки фронтенда:

```
/
  index.html           # публичное меню
  data/menu.json       # список позиций пива
  admin/index.html     # оболочка Decap CMS
  admin/config.yml     # бэкенд GitHub + поля
  oauth-worker/        # OAuth-прокси на Cloudflare Worker
    wrangler.toml
    src/index.js
  README.md
```

Код Worker лежит в этом же репозитории и попадает на Pages как статические файлы. Это безопасно: в коде нет секретов, `Client ID` и `Client Secret` задаются только в Cloudflare через `wrangler secret put`.

## Локальный запуск

1. Отдать корень проекта любым статическим сервером, например `npx serve -l 8765` (открыть `http://localhost:8765/`).
2. Для админки в соседнем терминале запустить `npx decap-server` (порт 8081) и открыть `http://localhost:8765/admin/`.

С `local_backend: true` Decap на localhost пишет изменения прямо в `data/menu.json` без коммита. На GitHub Pages эта настройка игнорируется, там используется бэкенд `github`.

## План реализации

### 1. Данные и публичная страница

- Завести `data/menu.json` и `index.html`.
- Опрос: каждые 15 с, сначала Worker `/menu`, при ошибке — `data/menu.json` с Pages; оба с `?t=` и `cache: 'no-store'`. На localhost — только локальный файл.
- Относительный путь к JSON, чтобы сайт работал и в корне Pages, и по subpath `/BeerHouseMenu/`.
- При ошибке fetch — не сбрасывать карточку.
- При `available: false` — состояние «нет в наличии».
- Без фреймворков: HTML + CSS + небольшой JS.

### 2. Decap CMS

- `admin/index.html` — оболочка CMS с CDN (без npm).
- `admin/config.yml`:
  - `backend.name: github`;
  - `repo: RobertUptodateman/BeerHouseMenu`;
  - `branch: master`;
  - `base_url` — URL Cloudflare Worker (без завершающего `/`);
  - коллекция типа `files`, один файл `data/menu.json`;
  - поля 1:1 со структурой JSON (`string` / `number` / `boolean`).
- Сначала можно проверить форму с `local_backend: true` и `npx decap-server`.
- Для критерия «вход через GitHub» локальный бэкенд выключается, подключаются Worker и OAuth App.

### 3. GitHub OAuth и Cloudflare Worker

Worker (`oauth-worker/src/index.js`):

- `GET /auth` — ставит cookie со случайным `state` и редиректит на GitHub;
- `GET /callback` — сверяет `state`, обменивает `code` на `access_token` и отдаёт popup-страницу, которая передаёт токен окну CMS через `postMessage`;
- токен уходит только окну с origin из `ALLOWED_ORIGIN` (`wrangler.toml`), поэтому CORS не нужен;
- `GET /menu` — отдаёт `data/menu.json` из ветки `MENU_BRANCH` через GitHub API, с кэшем 5 с и CORS только для `ALLOWED_ORIGIN`.

Для `/menu` нужен токен только на чтение (без него лимит GitHub API — 60 запросов в час, этого мало):

1. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate new token.
2. Repository access — Only select repositories → `BeerHouseMenu`; Permissions → Contents: **Read-only**.
3. В папке `oauth-worker/`: `npx wrangler secret put MENU_TOKEN` и вставить токен.

Пока токена нет, `/menu` отвечает 503, и страница автоматически берёт JSON с Pages.

Порядок настройки:

1. Задеплоить Worker, чтобы узнать его URL (в папке `oauth-worker/`):

   ```bash
   npx wrangler login
   npx wrangler deploy
   ```

   Получится адрес вида `https://bh-menu-oauth.<аккаунт>.workers.dev`.
2. GitHub → Settings → Developer settings → **OAuth Apps** → New (не GitHub App):
   - Homepage URL — `https://robertuptodateman.github.io/BeerHouseMenu/`;
   - Authorization callback URL — `https://bh-menu-oauth.<аккаунт>.workers.dev/callback`.
3. Сгенерировать Client Secret и сохранить оба значения в Worker:

   ```bash
   npx wrangler secret put GITHUB_CLIENT_ID
   npx wrangler secret put GITHUB_CLIENT_SECRET
   ```

4. В `admin/config.yml` раскомментировать `base_url` и вписать URL Worker без завершающего `/`.

Доступ в админку = GitHub-аккаунт, который может войти через это OAuth App и имеет push в репозиторий.

### 4. GitHub Pages

- Источник: ветка `master`, папка `/` (root).
- Если репозиторий не `username.github.io`, сайт будет по адресу `https://<user>.github.io/BeerHouseMenu/` — это нужно учесть в Homepage OAuth App.

### 5. Склейка и проверка

Порядок коммитов при реализации:

1. `data/menu.json` + `index.html` (карточка, опрос, ошибка fetch).
2. `admin/` + `config.yml` (сначала локальный бэкенд).
3. Worker + OAuth App + `base_url` в конфиге CMS.
4. GitHub Pages и полный цикл.

## Риски

- **Кэш Pages.** Без `?t=` и `cache: 'no-store'` меню может показывать старый JSON.
- **Subpath репозитория.** Неверный базовый URL ломает `/admin/` и `fetch`.
- **Формат JSON.** Decap `files` пишет объект верхнего уровня, поэтому список лежит в поле `taps`. Страница также понимает старые форматы (`core`/`guest`, `beers` и одна позиция).
- **Очень много позиций.** Шрифт не опускается ниже 8 px; если меню не помещается даже так, длинные названия обрезаются многоточием. На Full HD при 12 + 12 позициях названия идут шрифтом ~38 px.
- **Разделитель.** Если удалить разделитель, все позиции уйдут в левую колонку; вернуть его можно через «Добавить позицию» → «Разделитель «Гостевые краны»». Если разделителей несколько, учитывается первый.
- **Права токена.** У OAuth App должен быть доступ к репозиторию.
- **Origin Worker.** Если `ALLOWED_ORIGIN` не совпадает с origin сайта (схема + домен без пути), popup не передаст токен и вход зависнет.
- **Задержка CDN.** Сборка Pages занимает ~40 с, плюс кэш CDN до 10 минут. Поэтому основной источник — Worker `/menu`; Pages остаётся запасным.
- **Срок токена `MENU_TOKEN`.** У fine-grained токена есть срок действия. Когда он истечёт, меню продолжит обновляться через Pages, но медленнее; нужно выпустить новый токен и заново выполнить `wrangler secret put MENU_TOKEN`.

## Требования к реализации

- Максимально простая структура репозитория.
- Минимум зависимостей.
- Decap CMS работает с одним JSON-файлом.
- Публичная страница устойчива к недоступному JSON.
- Цепочка «вход → редактирование → коммит → обновление сайта» работает стабильно.

## Критерии готовности

Этап 1 (выполнен):

- Можно войти в `/admin/` через GitHub.
- Можно изменить данные позиции пива и сохранить.
- Изменения появляются в JSON-файле в репозитории.
- Публичная страница сама подхватывает обновлённые данные и отображает их.

Этап 2:

- На телевизоре в альбомной ориентации всё меню помещается на одном экране без прокрутки при любом числе позиций.
- Шрифт автоматически становится меньше при добавлении позиций и больше при удалении.
- Позиции можно добавлять, удалять и переставлять в админке, номер крана проставляется автоматически.
- Две колонки (базовые и гостевые), светлый фон в цветах логотипа, маркеры цвета пива (выполнено).
